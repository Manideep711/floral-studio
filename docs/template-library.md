# Expanded template and flower library

Sizes: Mini has 3 layers and a 92-unit base radius; Small has 5 and 122; Medium has 7 and 150; Large has 7 and 180. Large is wider at the same layer count. Existing saved drafts retain their original dimensions.

There are 24 templates. Filters cover size, colour family, shape, arrangement pattern and included flowers. The gallery uses build-time, lazy-loaded WebP thumbnails rather than detailed SVGs rendered on the device. Templates preserve the user's title and dedication and can be undone.

Height is an independent choice: Short, Medium or Tall sets each layer's rise to 16, 24 or 32 units. Template height retains the original profile. Width, layer count, flowers, colours and accents stay unchanged. Large + Short can therefore be wider and lower than Small + Tall. Pre-rendered side-profile thumbnails update before applying a template; the gallery remains filtered by size and the other categories. Shape uses Stepped rather than Tall to distinguish silhouette from height.

Roses have original 2D illustrations and procedural 3D petals in crimson, blush and ivory. They work as layers and spaced accents, in backups, thumbnails and the garden. Roses are identified as a creative garden-flower option; the guided family tradition still starts with Tangedu. The cupped double-rose shape is informed by the RHS rose descriptions: https://www.rhs.org.uk/plants/roses/choosing-the-best

For an existing Supabase project, apply supabase/flower-library-upgrade.sql before publishing rose arrangements. Fresh installs use the updated garden.sql. The migration changes only the permitted flower/color combinations; ownership, consent, moderation and quotas remain enforced. This workspace has no configured live Supabase credentials, so the migration was tested in local PostgreSQL rather than applied remotely.

Validation: TypeScript and production build passed. All 37 tests passed, including every template's schema, taper, artwork, undo, both rose geometry levels and the PostgreSQL flower/color validator. The independent-height test validates all 24 templates at all three heights, unchanged attributes apart from rise, side-profile flower counts, and Large + Short versus Small + Tall. Browser checks covered combined filters, empty-state reset, mobile controls, a rose arrangement in 2D/3D, and Undo. Short and Tall previews were visually checked; the new controls are 44px tall at the observed 417px mobile viewport with no horizontal overflow. Backups before and after the earlier rendering check matched exactly; this height-preview check did not apply a template or change the saved draft. No physical phone performance benchmark was run.

Performance fix: 96 pre-rendered 360x240 WebP images cover every template and height, totaling 736 KB, with the largest 13 KB. The build regenerates the assets using the existing Sharp dependency. The gallery no longer imports the SVG renderer or generates layouts during render. A test enforces complete assets, valid WebP dimensions and a 20 KB per-preview budget. Size and Height share one row; extra filters are in a native details disclosure to keep previews visible on mobile.

Additional editor fixes: ArrangementCanvas now keeps one bounded offscreen bitmap per layer. Unchanged layers are composited instead of re-stamping every flower during slider updates; cache keys include dimensions, projection, seed, layout version, height fit and layer attributes. Removed layers are evicted. A five-layer browser check painted one layer after a radius change (0.8 ms draw versus 2.3 ms for the initial five-layer paint); this is an observed browser frame, not a physical-phone benchmark. Undo restored an identical downloaded draft. The 3D loading/illustrated view uses the same raster renderer; an unavailable WebGL Canvas now explicitly activates the fallback rather than leaving inactive 3D controls visible. WebGL was unavailable in the test browser, so actual GPU rendering performance was not measured.

Template Size and Height are visible pressed-state buttons with Motion tap feedback and reduced-motion support. The other category filters remain available under More filters. Mobile Large + Short selection and image loading were checked. Production build and all 37 tests pass after these changes.

3D startup correction: the previous Canvas fallback component ran an effect calling onFailure. React Three Fiber mounts the Canvas fallback as ordinary canvas child content even on WebGL-capable browsers, so this effect incorrectly disabled a working renderer. It is now passive descriptive text. BloomViewer and FlowerStory let the actual renderer/error boundary determine support instead of allocating and destroying probe contexts. Genuine failure supports manual Retry 3D in lighter mode; story errors activate a single raster fallback. The earlier test-browser statement that WebGL was unavailable was caused by this application bug. Verified actual 3D rendering on the homepage and in the studio, enabled camera rotation, and one WebGL canvas with 393 flowers and 15 draw calls. Production build/TypeScript and all 37 tests pass.
